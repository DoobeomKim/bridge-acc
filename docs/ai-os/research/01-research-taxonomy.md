# Company Research Taxonomy

Status: Active  
Version: 1.0.0  
Constitution: `BRIDGE_CONSTITUTION.md` version 1.0.0

## 목적

기업 조사는 회사 소개문을 만드는 작업이 아니다. 공개정보를 항목별로 확인하고, 무엇을 알았고 무엇을 아직 모르는지 분리하여 사람이 다음 영업 판단을 내릴 수 있게 하는 작업이다.

조사 결과는 사실, 추론, 미확인 정보를 섞지 않는다. 찾지 못한 정보도 삭제하지 않고 조사 결과로 남긴다.

## 항목별 상태

모든 조사 항목은 다음 세 상태 중 하나를 가진다.

| 상태 | 의미 | 사용 조건 |
| --- | --- | --- |
| `confirmed` · 확인됨 | 공개 근거로 해당 정보를 확인했다. | 내용을 직접 뒷받침하는 출처가 최소 1개 연결되어야 한다. 중요한 회사 식별 정보는 공식 출처를 우선한다. |
| `not_found` · 찾지 못함 | 해당 항목을 실제로 검색했지만 공개정보를 발견하지 못했다. | 검색한 범위, 확인일, 검색어 또는 확인한 채널을 기록해야 한다. 회사에 해당 활동이 없다고 단정하지 않는다. |
| `needs_research` · 추가 조사 필요 | 단서는 있지만 근거가 부족하거나, 출처가 약하거나, 서로 충돌한다. | 무엇이 부족하고 다음에 어디를 확인할지 기록해야 한다. |

아직 조사하지 않은 항목은 레코드를 만들지 않는다. `not_found`는 미조사 상태가 아니다.

## 조사 항목

### 1. 회사·법인 기본정보

확인 내용:

- 정확한 법인명
- 브랜드명과 법인명 구분
- 본사·자회사·지사 관계
- 국가, 도시, 주소
- 공식 웹사이트
- 법인등록번호 또는 공개된 설립정보

완료 조건:

- 정확한 대상 법인을 식별할 수 있어야 한다.
- 회사 공식 페이지, 법인등록 또는 정부 자료 중 하나를 우선 근거로 사용한다.
- 동명의 다른 회사나 그룹 전체와 혼동 가능성이 남으면 `needs_research`다.

### 2. 사업·제품

확인 내용:

- 주요 사업 분야
- 주요 제품·서비스
- 유럽·독일에서 실제 취급하는 사업
- 주요 고객 산업

완료 조건:

- 회사 공식 사업·제품 페이지로 유럽 대상 사업을 최소 하나 확인한다.
- 그룹 전체 사업과 독일 법인의 실제 역할을 구분하지 못하면 `needs_research`다.

### 3. 최근 사업 변화

확인 내용:

- 최근 투자·시설 개설
- 제품 출시
- 유럽 시장 확장
- 파트너십
- 조직 확대·축소
- 인수·매각·사업 철수

완료 조건:

- 최근 24개월 자료를 우선 확인한다.
- 사건, 발표일, 실제 발생일을 가능한 범위에서 구분한다.
- 과거 정보만 발견되면 현재 변화로 표현하지 않는다.

### 4. 마케팅 활동

확인 내용:

- 운영 채널
- 최근 게시 활동
- 주요 메시지와 타깃 고객
- 캠페인, 고객사례, 제품 마케팅
- CTA, 문의, 브로슈어, 랜딩페이지
- 사용 언어와 유럽 현지화

완료 조건:

- 공식 웹사이트나 공식 SNS의 실제 콘텐츠를 확인한다.
- 활동이 활발하다는 판단은 최근 게시물이나 캠페인 사례를 근거로 한다.
- 팔로워 수만으로 마케팅 수준을 판단하지 않는다.

### 5. 기존 콘텐츠 수준

확인 내용:

- 웹사이트·뉴스룸·블로그
- 영상·YouTube 활용
- 기술 설명과 고객사례
- 현장·사람 중심 콘텐츠
- 다국어 콘텐츠
- 콘텐츠에서 영업 행동으로의 연결

완료 조건:

- 실제 콘텐츠 표본을 최소 2개 확인한다.
- 콘텐츠가 부족하다고 단정하기 전에 공식 채널을 확인한다.
- 품질 평가는 관찰 사실과 AI 해석을 분리한다.

### 6. 채용·조직 변화

확인 내용:

- 현재 채용공고
- 최근 확대 중인 직무
- 영업·마케팅·사업개발 조직
- Customer Solution·기술지원 조직
- 공개된 담당 조직

완료 조건:

- 공식 채용 페이지를 우선하고 채용 플랫폼은 보조 근거로 사용한다.
- 만료된 공고를 현재 채용으로 표현하지 않는다.
- 개인 연락처를 수집하지 않고 공개된 업무 역할만 기록한다.

### 7. 박람회·행사

확인 내용:

- 예정된 박람회 참가
- 최근 참가 이력
- Tech Day, 웨비나, 고객행사
- 발표·부스·파트너 행사

완료 조건:

- 박람회 공식 참가사 목록이나 회사 공식 발표를 우선한다.
- 참가 가능성을 참가 사실처럼 표현하지 않는다.
- 행사명과 날짜를 함께 기록한다.

### 8. 공개입찰·지원사업

확인 내용:

- EU·독일 공공 지원사업
- 공동 연구 컨소시엄
- 공공조달 발주·수주
- 민간 공급업체 공개 모집
- 기술·유통·사업 파트너 모집

완료 조건:

- EU, 정부, 조달기관 또는 회사 공식 모집자료를 우선한다.
- 지원사업, 공공입찰, 민간 파트너 모집을 서로 구분한다.
- 프로젝트 기간, 회사 역할, 확인 가능한 예산을 구분해 기록한다.

### 9. 담당 조직·접근 경로

확인 내용:

- 관련 업무를 담당할 가능성이 있는 조직
- 공식 문의 채널
- 지역 Sales·Marketing·Customer Solution 조직
- 본사와 유럽 법인의 역할 관계

완료 조건:

- 담당 개인을 억지로 특정하지 않아도 된다.
- 최소한 확인해야 할 조직 또는 공식 접근 채널을 제시한다.
- 실제 의사결정자는 공개자료만으로 확정하지 않는다.

### 10. 미팅에서 확인할 사항

확인 내용:

- 공개정보로 알 수 없는 사업 우선순위
- 예산과 일정
- 기존 업체
- 본사·현지법인 결정권
- 실제 문제와 성공 기준
- 다음 파일럿 가능성

완료 조건:

- 공개정보의 공백과 영업 가설에서 질문을 생성한다.
- 답을 추측하지 않는다.
- 질문마다 확인 이유와 적절한 확인 대상을 기록한다.

## 조사 전체 상태

항목별 상태를 바탕으로 조사 전체 상태를 다음처럼 표시한다.

| 전체 상태 | 조건 |
| --- | --- |
| `insufficient` · 근거 부족 | 정확한 법인을 확인하지 못했거나 공식 출처가 하나도 없다. 점수와 영업 추천을 확정하지 않는다. |
| `partial` · 일부 확인 | 법인은 확인했지만 핵심 항목에 `needs_research`가 남아 있다. 부족한 항목을 명시한다. |
| `review_ready` · 사람 검토 가능 | 정확한 법인과 공식 출처가 있고, 각 항목이 `confirmed` 또는 근거가 기록된 `not_found` 상태다. 사람에게 판단을 요청할 수 있다. |

`review_ready`는 영업 적합 판정이 아니다. 조사 자료가 사람 검토에 충분한 형식을 갖췄다는 뜻이다.

## 최소 출력

기업 조사 결과에는 반드시 다음이 포함된다.

- 정확한 대상 회사
- 항목별 상태와 요약
- 확인된 사실
- AI의 해석
- 찾지 못한 정보
- 추가 조사할 정보
- 미팅에서 확인할 질문
- 연결된 원본 출처
- 확인일
- 조사 전체 상태
- 다음 권장 행동

## 변경 원칙

- 이 분류체계는 회사 헌법보다 낮은 정책이다.
- AI는 항목 추가나 완료 조건 변경을 제안할 수 있다.
- 승인된 새 버전은 이전 버전을 삭제하지 않는다.
- 모든 조사 실행은 사용한 정책 버전을 기록한다.
